# MEDNEXUS Data Dictionary

## Purpose

The canonical field-level data dictionary is generated by the pipeline from the same source frames used by analytics. This reduces drift between code and documentation.

Generated artifact:

artifacts/validation/data_dictionary.csv

For every source field it records:

- table;
- column;
- observed data type;
- semantic role;
- field description;
- foreign-key target where applicable;
- observed nullability and null count;
- observed cardinality;
- example synthetic value;
- source classification.

## Table register

The pipeline also generates:

artifacts/validation/table_register.csv

For every source table it records:

- business grain;
- primary key or documented composite-key state;
- foreign-key paths;
- current row count;
- table role/cardinality class;
- refresh/analytical cadence;
- date field where applicable;
- business meaning;
- source classification.

## Governance rule

The generated dictionary is evidence for the current executable schema. It does not replace business definitions in the KPI Dictionary, methodology documents, provenance documentation, or semantic-model documentation.

A new field is not considered governed merely because it appears in the CSV. New analytical fields still require a defensible business meaning, grain, calculation, validation method, and limitation statement where applicable.

## Synthetic-data disclosure

The default MEDNEXUS enterprise dataset is synthetic. Example values in the generated dictionary are synthetic examples and must not be represented as proprietary company data.
